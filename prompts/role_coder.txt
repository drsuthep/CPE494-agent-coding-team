PER-FILE-TYPE CONTRACTS:

== Django Model (models.py) ==
- Class name in PascalCase.
- Field names in snake_case.
- Include the entity's display code field (per the logic spec and active sprint scope) with unique=True. Field is `code` for Customer/Product, `invoice_no` for Invoice, otherwise as declared in the sprint scope.
- Include `updated_at = models.DateTimeField(auto_now=True)`.
- Include `__str__(self)` returning the display code.
- Include `class Meta` with `ordering` where list ordering matters.
- ForeignKey relations require explicit `on_delete=` (typically `models.PROTECT` or `models.CASCADE`).
- Imports: `from django.db import models` at minimum.

== ModelForm (forms.py) ==
- Subclass `forms.ModelForm`.
- Set `Meta.model` and `Meta.fields` (explicit list, NEVER `__all__`).
- Apply Bootstrap classes via widget attrs: `widgets = {"name": forms.TextInput(attrs={"class": "form-control"}), ...}`.
- For ForeignKey fields, render as a hidden input (the form's underlying `<input type="hidden" name="customer">`) — the visible code + LOV button live in the template, NOT in the ModelForm widget.
- Imports: `from django import forms` and the model.

== Views (views.py) ==
- Function-based views unless the task contract says otherwise.
- Each view has a docstring.
- For per-entity apps that have shared list/form view modules available, the per-entity view delegates to the shared module (e.g., `return shared_list_view(request, model=Customer, columns=[...])`). Do NOT duplicate logic that the shared module already covers.
- Save behavior: GET renders the form. POST validates. On success, save → `messages.success(request, "Saving... Save successful")` → redirect to the SAME record's edit URL (PRG pattern). On failure, re-render with the bound form so errors display.
- Use named URL references in `redirect()` calls — never hard-code paths like `redirect('/customers/')`.
- For Delete views: POST only, get_object_or_404, delete, redirect to the entity's list view.
- Imports: `from django.shortcuts import render, redirect, get_object_or_404`, `from django.contrib import messages`, the form, the model.

== App URLs (app/urls.py) ==
- First line of urlpatterns block: declare `app_name = '<app>'` (e.g., `app_name = 'customers'`).
- Use `path()` with named patterns: `name="list"`, `name="create"`, `name="edit"`, `name="delete"`, etc.
- Pattern names align with view function names where possible.
- Imports: `from django.urls import path`, `from . import views`.

== Project URLs edit (project/urls.py) ==
- Preserve existing `path('admin/', admin.site.urls)` line.
- Add `path('', include('<app>.urls'))` for landing + app routes.
- Imports: `from django.contrib import admin`, `from django.urls import path, include`.

== Settings.py (create or edit) ==
- Add the new app to `INSTALLED_APPS`.
- `DEBUG = True` (teaching default).
- `ALLOWED_HOSTS = ['*']` (teaching default).
- `LANGUAGE_CODE = 'en-us'`, `TIME_ZONE = 'UTC'`.
- `TEMPLATES[0]['DIRS'] = [BASE_DIR / 'templates']`.
- `STATIC_URL = 'static/'`.
- `DATABASES` uses SQLite: `{'ENGINE': 'django.db.backends.sqlite3', 'NAME': BASE_DIR / 'db.sqlite3'}`.
- `SECRET_KEY` may be a placeholder string clearly marked TEACHING.
- `DEFAULT_AUTO_FIELD = 'django.db.models.BigAutoField'`.
- `MESSAGE_TAGS` may map `messages.SUCCESS` to `'success'` for Bootstrap class compatibility.

== Django Template (.html) ==
- Templates in `templates/<app>/<page>.html` extend `templates/base.html`.
- First non-comment line: `{% extends "base.html" %}`.
- Define `{% block title %}<page title>{% endblock %}` and `{% block content %}...{% endblock %}`.
- Required fields: red asterisk via `<span class="text-danger">*</span>` placed AFTER the label text.
- Forms include `{% csrf_token %}`.
- Form action row: Save (primary, type="submit", fa-floppy-disk, title="Save"), Delete if editing existing (danger, fa-trash, title="Delete"), Close (secondary, fa-xmark, title="Close").
- For ForeignKey fields, render the LOV pattern: a hidden input with the FK's id, a visible read-only input with the related record's display code, and a small LOV button (fa-list, title="Open list of values"). See ui_specs/form_workflow.md Section 9.
- All forms attach the dirty-bit listener (inherited from base.html).
- Numeric/currency cells/inputs use `text-end`.
- Tables wrapped in `.table-responsive`.

== base.html ==
- Bootstrap 5 + Font Awesome 6 via CDN.
- Zen Green CSS tokens in a `<style>` block.
- Top navbar with brand and entity nav links.
- `{% block title %}` and `{% block content %}` defined.
- Render Django messages as a flash stack with a 2-second auto-fade JS handler (per form_workflow.md Section 6).
- Include the dirty-bit JS listener (per form_workflow.md Section 5).

== tests.py ==
- Subclass `django.test.TestCase`.
- One TestCase class per scenario group.
- Test method names match the test_cases names from the task contract: `test_<entity>_<scenario>`.
- Every test_case in the task contract maps to at least one test method.
- Use `self.client.get(...)`, `self.client.post(...)`, `self.assertEqual`, `self.assertContains`, `self.assertRedirects`, `self.assertTrue/False`.
- For form validation: include at least one unhappy-path test that posts invalid data.
- For save flash: assert response contains "Saving... Save successful" or that `messages` framework received a success message.
- Imports: `from django.test import TestCase`, the model.
