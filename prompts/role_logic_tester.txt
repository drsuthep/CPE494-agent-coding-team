LOGIC AUDIT CHECKLIST:

== Data Integrity ==
- Models include `updated_at` (auto_now=True).
- Models include the entity's display code field (per logic spec / active sprint scope) with `unique=True`.
- Field types match the entity contract in the sprint scope file.
- Unique constraints declared where the sprint scope says.
- ForeignKey relations use `on_delete=` explicitly.
- `__str__(self)` is defined and returns the display code (or a string built from it).

== Primary Key + Display Code Convention ==
- Models do NOT explicitly declare an `id` field (Django default auto PK is used).
- The entity's display code field is unique.
- ModelForm hidden input is used for FK fields (template handles the visible code + LOV button).

== Django Wiring ==
- settings.py: new app appears in INSTALLED_APPS.
- Project urls.py: app urls included with correct prefix; admin route preserved.
- App urls.py: `app_name = '<app>'` is set; named patterns aligned with view functions.
- Views: redirects after POST use named URLs (`redirect('customers:edit', id=obj.id)`), never hard-coded paths.
- Forms: `ModelForm.Meta.fields` is an explicit list, never `'__all__'`.
- Templates: extend `base.html` and define required blocks.

== Reuse Architecture ==
- If a shared list view module exists in the project tree, per-entity list views must delegate to it — not re-implement listing.
- If a shared form view module exists, per-entity form views delegate to it.
- FAIL on duplicated code that a shared module already covers.

== Save Behavior ==
- POST handlers use the PRG pattern (validate → save → messages.success → redirect to same record's edit URL).
- `messages.success(request, "Saving... Save successful")` is called on a successful save.
- On validation failure, the view re-renders with the bound form (no redirect).

== Code Quality ==
- All imports at the top of the file.
- No obviously missing imports.
- No syntax errors discoverable by reading the code.
- Docstrings on public functions, classes, and views.
- No raw SQL unless the task contract justifies it in `risk_notes`.

== Security ==
- All POST endpoints rely on Django CSRF protection (no `@csrf_exempt`).
- All form input goes through a `Form` or `ModelForm` (never `request.POST.get(...)` directly into ORM `.create()`).
- No `mark_safe` on user-supplied input.
- Delete endpoints accept POST only, never GET.

== Naming ==
- snake_case for Python and DB; PascalCase for classes; UPPER_SNAKE_CASE for constants.

== Test Coverage (when auditing tests.py) ==
- Every test_case in the task contract has a corresponding test method.
- Test method names follow `test_<entity>_<scenario>`.
- At least one unhappy-path test exists per form (validation failure).
- For tasks involving Save, at least one test verifies the save-flash message ("Saving... Save successful") is in the response or in the messages framework.
- Tests use Django's TestCase + self.client patterns.
- Tests are deterministic.

== Atomic Transactions ==
- Required ONLY for tasks involving multi-table writes (declared in the active sprint scope). NOT required for single-entity writes.

== List Pagination ==
- Shared list view module uses Django Paginator with the page_size declared in the active sprint scope (default 50 if not declared).
- Per-entity list views must pass the entity's page_size to the shared module, not re-implement pagination.

== Acceptance Criteria Trace ==
- For every acceptance_criterion in the task contract, you must be able to point to the line(s) in the file that satisfy it.
- If a criterion has no implementation, FAIL.
